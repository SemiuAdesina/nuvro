# Repository tree

This document is the canonical record of the NUVRO repository structure, including the
directories that are reserved but intentionally empty.

Git does not track empty directories. Rather than adding placeholder source files or
`.gitkeep` markers to keep them alive, the reserved boundaries are recorded here. A directory
appears in the working tree when its first real file is written.

## Root

```
nuvro/
├── backend/          Go modular monolith
├── clients/
│   ├── ios/          Native SwiftUI application and local Swift packages
│   └── android/      Native Kotlin and Jetpack Compose application
├── contracts/        OpenAPI contract, source of truth for both clients
├── design/           Brand direction, onboarding art plan, design tokens
├── docs/             Architecture, product, standards, decision records
├── infra/            Local Docker Compose and the backend container build
├── scripts/          Repository quality gates
├── .github/          CI workflows, dependency updates, pull request template
├── .editorconfig
├── .env.example
├── .gitattributes
├── .gitignore
├── CLAUDE.md
├── CONTRIBUTING.md
├── SECURITY.md
├── Makefile
└── README.md
```

There is no `ml/` directory. Custom machine learning is a future decision that requires its
own record, described in `overview.md`.

A target is declared in `Package.swift` when its first real source file is written. Declaring
a target whose directory is empty makes the package fail to build, so the remaining module
plan is recorded in `clients/ios/README.md` rather than as empty targets.

The Xcode project is generated from `project.yml` with xcodegen and is not committed. It is a
machine-generated file reproducible from the spec, so it falls under the generated-code rule.

## Phase 1 additions

Existing package locations are retained. `domain/trip`, `domain/user`,
`domain/destination`, `domain/evidence`, `engine/media`, `engine/requirements`,
`usecase/plan`, `usecase/system`, `adapter/postgres`, `adapter/redis`,
`platform/telemetry`, `transport/http/authentication` and generated
`transport/http/api` now exist. Migrations, queries and real integration tests exist.
`internal/contract` supports the `cmd/contract` validation/bundling tool; `cmd/migrate`
is a Goose operator command. Neither is a service.

Contracts now have released `openapi/v1` and proposed `openapi/drafts` roots.
Unversioned Phase 0 files remain for prototype compatibility and are not generator
inputs. Product-specific path files are added when their vertical slices are real.

Phase 1 completion added `platform/id/uuid.go` (canonical version 4 entity identifiers),
`transport/http/middleware/idempotency.go` (header format boundary), `adapter/redis/key.go`
(namespaced key formatter) and fuzz targets beside each parser. The drafts root holds
`openapi.yaml`, `paths/{profile,trips}.yaml`, `components/parameters/idempotency-key.yaml`
and `schemas/{profile,preferences,trip,trip-input,trip-patch,trip-page}.yaml`, all YAML.
